# Facebook campaign outage: October 14–16, 2026

## Confirmed cause

Production run `a04c9acd-57a7-4b2c-8970-bcf579e80983` failed at the first model invocation. Its saved exception chain ends in OpenAI `RateLimitError`, HTTP 429, with `provider_type=insufficient_quota` and `provider_code=credit_balance_exhausted`. The provider reported no remaining credits. Request ID: `req_74a37b9d3cf645058de8eea0ec49737e`.

The persisted history shows October 13 (`74eb1ea3-6e5c-44b8-89cd-45b6bfcc67cd`) published successfully. October 14 (`f3f8e0d1-4346-42e4-b521-fbad4512a308`), October 15 (`a735c8c5-964a-482d-be66-87ea06c878f5`), and October 16 failed with the same exhausted-credit message. Each reached three generation attempts. This evidence establishes a provider billing/quota outage, not a demonstrated editorial-selection or LangSmith regression. Billing history was not available to establish why credits were depleted.

Generation failed before an approved artifact existed. The publishing workflow correctly blocked instead of sending incomplete content. Its failure was a downstream symptom, not a second Facebook delivery error.

## Contributing operational defects

- CrewAI wraps the provider exception in `RuntimeError`. The API retained the useful inner diagnostic but exposed only the wrapper in its summary.
- Recovery treated all HTTP 429 responses as transient, including exhausted billing credits.
- The n8n result summarizer selected the top-level `blocked` outcome before the more informative nested campaign reason.
- The error workflow wrote events back to CrewAI but did not send Slack/email notifications. It also depended on CrewAI being available.
- Readiness validated configuration and worker startup, not successful model billing access. Healthy service readiness did not mean campaign generation could succeed.

## Implemented remediation

Permanent billing/authentication failures now open a durable generation pause and expose actionable reasons. Transient network/provider errors retain bounded, jittered backoff, a maximum of three automatic generation attempts, and publishing-window checks. `Retry-After` seconds are honored (bounded to one hour). Known legacy billing errors cannot retry merely because an older run stored `retryable=true`.

An independent operational watchdog scans campaign state, queues eligible generation recovery, detects missing workflow heartbeats/stalled work, and delivers durable Slack/email alerts. Incident keys deduplicate repeated generation/publishing observations; reminders default to six hours. Separate channel queues support five bounded delivery attempts, lease recovery after process interruption, visible exhaustion and explicit operator retry. Successful recovery emits a resolution notice.

n8n templates add bounded transport retries, watchdog health checks, and independent Slack/SMTP fallback notifications when the primary alert service is unreachable or unhealthy. Fallbacks are throttled separately by channel and do not depend on the CrewAI API succeeding.

No recovery path automatically replays a Facebook send with an unknown outcome. Billing/authentication repairs require operator confirmation before generation resumes. An active agent is alerted as potentially stalled rather than forcibly restarted.

## External prerequisites

Restoring provider credits/access is an account action; redeployment alone cannot repair exhausted credits. SMTP sender credentials are required to deliver email to `bun2too@gmail.com`. Updating live n8n workflows requires its management API key. Check the operational runbook and deployment verification record for the actual activation status; prepared templates and passing tests do not prove those integrations are live.

Production inspection also found no configured Atlassian credentials. Existing `atlassian_sync_failed` events are independent of the model outage; Jira/Confluence synchronization still needs its own credentials.
